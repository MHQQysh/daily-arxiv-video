Sprout: Building Dynamic Memory While Reasoning for Agentic Video Understanding

2026-09-28 · 原文 · 翻译 · 2609.35497

提出 Sprout，一个面向智能体（agentic）长视频理解的框架，核心思想是在推理过程中动态构建记忆（build memory while reasoning），而非传统的"先构建离线记忆、再静态推理"。 现有方法（如 Qwen-MM-Plugins、MERIT 等）在回答任何问题前对整个视频构建静态记忆；当问题很少时，构建成本浪费；当问题很多时，记忆从不更新，无法累积跨问题的知识。 Sprout 通过 watch（观看）、remember（记忆）、revisit（回看） 三种动作，让记忆随时间生长为"时间树"，只在问题需要的地方添加细节，并去除已记录片段的视频输入以降低上下文占用。

Card 03 核心贡献

核心贡献

  • 指出现有 build-then-reasoning 管线的两个缺陷：离线构建对少问题视频浪费资源，静态记忆无法积累先前推理得到的洞察。
  • 提出 Sprout：以时间树为记忆结构，在回答问题的过程中通过低帧率观看、逐段写入粗粒度节点、以及高帧率回看补充细粒度子节点的方式动态构建记忆。
  • 验证"将视频帧转为文本后从上下文移除"的做法可大幅压缩上下文，且不损失准确率，某些设置下还有轻微提升。
  • 在三个基准、三种大模型上，Sprout 取得与代表性离线记忆方法相当或更好的准确率，且无需任何前置构建阶段，每问题上下文成本更低。
Card 04 方法描述

方法描述

  • 记忆由三部分组成：时间树（按时间组织的节点，存有事件摘要、观察到的事实、关键实体）、观看记录（记录视频已观看到的位置）、问题历史（之前的问题与答案）。
  • Watch：通过工具 read_next 按片段（chunk）以低帧率 f_c 观看未看过的视频，附带说话人标注的语音转录（如可用），每次只加载下一块。
  • Remember：观看后调用 write_chunk_memory 将片段写成 4–8 个粗粒度节点（每个含 5–10 条客观事实），随后该片段的视频帧即从上下文历史中移除，只保留文本。
  • Revisit：通过 search_memory 检索相关节点（支持文本匹配和时间窗口），用 view_node / view_time 以更高帧率 f_r 回看相关区间，再通过 refine_node / add_observation 写回细粒度子节点。
  • 问题结束后，答案写入问题历史；记忆和观看记录跨问题保留，使后续问题可以复用、细化已有节点或继续扩展未看视频。
  • 关键创新点：在线动态记忆（只在问题驱动下生长）、由粗到细的时间树、帧即用即释（release frames）的上下文管理机制。
Card 05 数据集与资源

数据集与资源

  • 评估数据集：LVBench（103 个时长级视频，1549 题）、Video-MME Long（300 个 30–60 分钟视频，900 题）、Video-Holmes（270 个短悬疑视频，1837 题）、EgoLifeQA（单参与者 Jake 的 44.3 小时 7 天录制，500 题）。
  • 模型：GPT-5、Qwen3.8-Max、Gemini 3.8 Flash；对比方法 Qwen-MM-Plugins 使用 Qwen3.7-Plus 预先构建记忆。
  • 配置：LVBench / Video-MME Long 上 read_next 用 10 分钟块、0.1 fps；GPT-5 因端点图像限制用 5 分钟块；Video-Holmes 用 30 秒块、1 fps；回看帧率可选 {1,2,4,8} fps，每视图最多 768 / 48 / 2048 帧（分别对应 Qwen3.8-Max / GPT-5 / Gemini）；每个问题最多 32 轮工具调用。
  • 代码已开源：https://github.com/HKUST-LongGroup/Sprout
Card 06 评估与结果

评估与结果

  • 主结果（Table 1）：Sprout 在 LVBench / Video-MME Long / Video-Holmes 上的准确率——GPT-5：73.4 / 80.4 / 56.7；Qwen3.8-Max：86.9 / 86.0 / 71.6；Gemini 3.8 Flash：88.2 / 91.2 / 76.8。
  • 对比 Qwen-MM-Plugins（Gemini 3.8 Flash 下 85.5 / 89.4 / 69.2），Sprout 在三个基准上均更优；相较 Direct 推理也有明显提升。
  • EgoLifeQA（Table 2）：Sprout 与 Qwen3.8-Max 结合的整体准确率为 80.6%，高于 Qwen-MM-Plugins 的 75.8%；与 Gemini 3.8 Flash 结合时为 80.6%+（原文此处未完整给出整体值，但从数值看优于直接推理）。
  • Token 成本：以 Gemini 3.8 Flash 为例，Sprout 在 LVBench 和 Video-MME Long 上每问题分别仅用 71.7K 和 99.3K tokens，比直接推理减少 74% 和 55%。
  • 通过"释放帧"操作，上下文长度从 L_t^retain = B_t + sum(v_j) 降为 L_t^release = B_t + v_t，即只保留最近一次观看的视觉帧。
  • 实验还表明：无需离线构建阶段、跨问题累积有效，且问题历史对后续回答有正向作用。
