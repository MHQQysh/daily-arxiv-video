The Missing Temporal Link: Temporal Context Routing for Script-Driven Audio-Video Generation

Card 03 核心贡献

核心贡献

  • 识别并形式化了脚本驱动生成中的时间错位问题：现有联合生成模型仅对齐音视频模态，未将脚本时序作为跨模态控制信号。
  • 提出 TCR 机制，将每个提示的时间区间转换为时长归一化的路由分数，作为偏置项添加到视频-文本和音频-文本交叉注意力 logits 中，实现镜头与对话提示的独立时序控制，且不引入任何可学习参数。
  • 设计粗到细数据构建流水线：Gemini 生成语义标注与粗粒度时间，PySceneDetect 精修镜头边界、WhisperX 对齐对话时间，最终在 0.1 秒网格上生成精细时序监督。
  • 在 200 条测试脚本上，相比最强开源基线将 Shot Boundary MAE 降低 96%（1.11 s → 0.042 s），Dialogue Acc@0.5s 从 28.3% 提升至 84.1%，同时保持视觉质量与音视频同步性能。
Card 04 方法描述

方法描述

  • 基于 LTX-2.3（22B 参数联合音视频生成模型）构建 TCR，仅修改其视频-文本和音频-文本交叉注意力模块，保留模态内自注意力和音视频交叉注意力不变。
  • 结构化脚本表示：采用 MTSS 架构，包含 Reference、Shot、Event、Global 四类提示；时间字段从文本输入中剥离，通过 token 级映射单独传递给 TCR。
  • 路由分数计算：对提示区间 [s_j, e_j] 计算中心 c_j 与半径 r_j，定义路由分数 B^m_ij = -β(t^m_i - c_j)²/(2r_j²)，在区间中心为 0、端点处为 -β/2，按时间距离平滑衰减；β 取 5。
  • 加性时间路由：路由分数与语义分数相加后取指数，等价于对未归一化注意力权重做乘性重加权，不改变文本、query 或 key 表示，从而保持底层生成器的视觉质量和音频-视频同步能力。
  • 训练采用 LoRA 适配器（TCR 本身无可学习参数），在原始联合 flow-matching 目标下优化，并在训练和推理阶段均施加 TCR。
Card 05 数据集与资源

数据集与资源

  • 训练数据：由两个短剧数据集构建的 57,022 个训练样本。
  • 测试数据：200 条测试脚本，包含 640 个 Shot 提示和 441 个对话提示，与训练集无源媒体重叠。
  • 模型规模：LTX-2.3 骨干模型，22B 参数；TCR 模块无新增参数，仅训练 LoRA 适配器。
  • 数据标注工具：Gemini（语义标注与粗时间）、PySceneDetect（镜头边界检测）、WhisperX（词级语音对齐）。
  • 生成配置：704×1280 分辨率、24 fps、目标时长输出。
Card 06 评估与结果

评估与结果

  • 端到端对比基线：Wan2.2、OVI、JoyAI-Echo、LTX-2.3；各模型均接收相同的镜头/对话描述和目标时间（无首帧条件）。
  • 评估指标：视觉质量（VBench 的 IQ、AES）、时间精度（Shot Boundary MAE、Shot IoU、镜头数量准确率、Dialogue Acc@0.5s）、语音与同步（WER、SyncNet Sync-C、Offset Acc）。
  • 关键结果：TCR 将 Shot Boundary MAE 从 1.11 s 降至 0.042 s（降幅 96%），Dialogue Acc@0.5s 从 28.3% 提升至 84.1%，同时视觉质量和音视频同步与基线相当。
  • 受控对比：仅改变时间算子时，TCR 相对两种时间基线将 Shot Boundary MAE 降低超过 60%，并取得最高 Dialogue Acc@0.5s。
  • 消融研究：使用粗时间标注替代细粒度标注会显著降低镜头和对话的时序精度，验证了数据构建流程的有效性。
  • 用户研究：在镜头时机、对话时机、脚本保真度、音视频同步、整体质量五个维度上，参与者均更偏好 TCR。
